    그리고 문서 재정렬(Re-ranking) 최적화에 훨씬 더 많은 역량을 쏟아야 합니다.

8. [과잉 엔지니어링 경계] 당신은 토론 중입니다. 1. REST 대 gRPC 2. Kafka 대 RabbitMQ 3. PostgreSQL 대 MongoDB. 그 동안 당신의 API는 분당 12개의 요청을 받습니다. 이 상황에 대해 어떻게 평가하십니까?
    
    ```
    이건 상상도 못 할 높은 부하를 고려한 과도한 설계 때문에 얼마나 많은 시간을 낭비했는지조차 가늠할 수 없네요. 
    그 시간에 수백 가지의 유용한 기능을 개발하는 게 훨씬 나았을 텐데요
    
    A. 실제 비즈니스 요구사항과 트래픽 규모를 완전히 무시한 전형적인 과잉 엔지니어링(Over-engineering)입니다.
    
    이유
    시스템 설계의 본질은 주어진 리소스와 시간 안에서 비즈니스 가치를 창출하는 것입니다. 
    분당 12개(0.2 RPS)의 요청은 가장 단순한 프레임워크와 단일 데이터베이스(모놀리스)만으로도 
    완벽하게 처리할 수 있습니다. 필요하지 않은 마이크로서비스 기술 스택의 트레이드오프를 논쟁하느라 
    실제 제품 기능 개발 시간을 낭비하는 것은 공학적 의사결정 실패입니다.
    
    확장
    시스템 아키텍처는 상상 속의 글로벌 규모가 아니라, 현재 마주한 트래픽과 요구사항을 충족하는 
    가장 단순한 설계에서 출발해야 합니다. 복잡한 분산 아키텍처(Kafka, gRPC 등)는 트래픽이 기하급수적으로 증가하여 
    단일 노드의 물리적 한계에 부딪히는 시점에, 철저히 모니터링 데이터를 기반으로 점진적으로 
    도입하는 것이 올바른 시니어 엔지니어의 태도입니다.
    ```

9. [GraphQL 도입 실패 원인] 왜 일부 팀은 1년 후에 GraphQL 도입을 후회하나요?
    
    ```java
    A. 프론트엔드의 데이터 패칭 편의성에 가려진 백엔드 인프라 유지보수(보안, 캐싱, 성능 최적화)의 기
    하급수적인 비용 증가를 과소평가했기 때문입니다.
    
    이유
    프론트엔드 개발자는 쿼리 한 줄로 원하는 데이터를 조합할 수 있어 초기 생산성이 높아 보입니다. 
    하지만 백엔드 팀은 악의적인 무한 쿼리 루프를 막기 위한 복잡도 비용 분석(Complexity Cost), 
    전체 리졸버를 방어하는 DataLoader 작성, 인프라 계층 캐싱의 상실 등 아키텍처 난이도 폭증을 경험하게 되어 
    도메인 로직보다 GraphQL 방어 인프라를 짜는 데 더 많은 리소스를 낭비하게 됩니다.
    
    확장
    "조직의 통신 문제가 데이터의 관계(Graph) 복잡성보다 클 때만" GraphQL을 도입해야 합니다. 
    단순한 CRUD 위주의 서비스나 모바일 등 다중 클라이언트 플랫폼이 존재하지 않는 환경에서는 
    REST API가 성능, 운영 편의성, 유지보수 측면에서 압도적으로 우수합니다.
    ```

<summary><strong>4. CORS vs CSRF 둘 다 웹 보안과 관련이 있지만, 매우 다른 문제를 해결합니다. CORS와 CSRF의 차이점을 간단한 용어로 설명해 줄 수 있나요?</strong></summary>

4. CORS vs CSRF 둘 다 웹 보안과 관련이 있지만, 매우 다른 문제를 해결합니다. CORS와 CSRF의 차이점을 간단한 용어로 설명해 줄 수 있나요?
    
    ```markdown
    CORS는 크로스 오리진 페이지가 읽을 수 있는 것을 제한합니다. 
    CSRF는 브라우저가 자동으로 보내는 쿠키를 악용합니다. 
    실질적으로: CORS 설정은 CSRF를 절대 해결하지 못합니다. 
    토큰과 SameSite가 필요합니다.
    
    CORS와 CSRF는 서로 다른 문제를 해결합니다.
    CORS: 다른 웹사이트의 JavaScript가 API 응답을 읽을 수 있는지 제어합니다.
    CSRF: 다른 웹사이트가 사용자의 로그인 쿠키를 사용하여 애플리케이션에 요청을 보내는 것을 방지합니다.
    
    CORS는 응답 액세스를 제어합니다.
    CSRF는 무단 요청을 제어합니다.
    ```
    

</details>
