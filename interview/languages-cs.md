3. [== vs ===] null == undefined → true / null === undefined → false 이유는?
    
    ```
    ==는 타입 강제를 하기 때문에 둘 다 값이 없는 것으로 취급합니다. 
    ===는 엄격한 타입 + 값을 확인합니다. 그리고 이들은 서로 다른 타입입니다.
    
    A. 느슨한 비교와 엄격 비교의 차이입니다.
    
    이유
    ==는 타입 변환 후 비교, ===는 타입과 값을 모두 비교합니다.
    
    확장
    예측 가능한 동작을 위해 === 사용이 권장됩니다.
    ```

4. [npm run dev vs start] npm run dev vs npm start 차이점은?
    
    ```
    A. 보통 npm run dev는 개발용, npm start는 운영 실행용입니다.
    
    왜 이렇게 판단했는지
    package.json의 script 관례와 실행 목적 기준
    
    이유
    - npm run dev: 개발 편의용 스크립트
      - nodemon, vite, next dev 같이 hot reload / watch / 디버깅 옵션 포함이 많음
    - npm start: 서비스 실행용 기본 스크립트
      - 보통 빌드된 결과 실행 또는 운영 환경 실행에 사용
    
    확장
    차이는 Node.js 자체 규칙이 아니라 package.json에 정의된 script 내용에 따라 결정됩니다.
    즉, 프로젝트마다 다를 수 있지만 일반적으로 dev는 개발, start는 운영 용도입니다.
    ```

    ```
    즉, 전체 관측 시간에서 Idle Task가 점유한 시간의 비율을 뺀 나머지가

    확장

    ```

14. [가비지 컬렉션(GC) 도달성 판단] 객체가 도달할 수 없게 되지만 여전히 다른 객체와 참조를 가지고 있을 때(순환 참조 등) Java의 가비지 컬렉터는 어떻게 작동하나요?
    
    ```
    A. GC Root에서 도달 불가능하다면 묶음 채로 수거 대상이 됩니다.
    
    이유
    GC는 메모리 해제 대상을 "단순 참조 존재 여부(Reference Counting)"가 아니라 
    "GC Root(실행 중인 스레드, 정적 변수 등)에서 도달 가능 여부(Reachability)"로 
    판단하기 때문입니다.
    
    확장
    객체들끼리 서로 참조를 맺고 있더라도(Island of Isolation), 
    GC Root에서 연결되는 경로가 끊어졌다면 메모리에서 정상적으로 회수됩니다. 
    단, static 컬렉션이나 캐시에 남아있어 의도치 않게 도달 가능한 상태가 유지되면 
    메모리 누수(Memory Leak)가 발생합니다.
    ```

    ```
    팀 버너스-리(Tim Berners-Lee)는 아폴로 워크스테이션(Apollo workstations)에서 이 패턴을 가져왔는데, 
    그곳에서 //는 로컬 머신을 떠나는 것을 의미하고 단일 슬래시는 로컬 경로를 의미했습니다. 
    그는 이후에 이 슬래시들이 불필요했다고 말했습니다.
    
    A. 호스트 머신 시스템을 지정하기 위해 사용된 역사적 컴퓨팅 문법 패턴입니다.
    
    이유
    웹의 창시자 팀 버너스-리(Tim Berners-Lee)가 아폴로 워크스테이션(Apollo workstations)에서 
    이 패턴을 차용했습니다. 과거 운영체제에서 단일 슬래시(`/`)는 로컬 파일 경로를 의미했고, 
    이중 슬래시(`//`)는 네트워크를 통해 외부 머신(호스트)으로 나가는 경계를 의미하는 예약어였기 때문입니다.

    발명자 본인도 훗날 `//` 기호는 기술적으로 완전히 불필요한 설계였으며 생략해도 작동에 무방했다고 회고했습니다.

    현재까지도 모든 인터넷 프로토콜 식별자(`scheme://host`)로 고정되어 사용되고 있습니다.
    ```
